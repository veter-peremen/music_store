# Музыкальный магазин — складской учёт винила

Учебный сквозной проект курса «Методология и практики DevOps» (Московский Политех).
HTTP API для учёта музыкантов, жанров, виниловых пластинок, поступлений и продаж.

Техническое задание — [TZ.md](TZ.md). Описание API — [docs/API.md](docs/API.md). Схема данных — [docs/SCHEMA.md](docs/SCHEMA.md).

## Стек

Node.js + Express, PostgreSQL, Knex (миграции и доступ к БД), zod (валидация), Jest + Supertest (тесты), ESLint + Prettier (качество).

## Запуск локально

### Что нужно заранее

- **Node.js 20+** — проверить: `node --version`
- **PostgreSQL 16** запущен и слушает порт (по умолчанию 5432) — проверить: `psql --version`

### Пошагово

```bash
# 1. Зависимости
npm install

# 2. Конфигурация: скопировать шаблон и вписать свои параметры БД
cp .env.example .env

# 3. Создать базу (один раз). Пароль спросит интерактивно:
createdb -U postgres music_store

# 4. Создать таблицы
npm run migrate

# 5. Демонстрационные данные (необязательно, но с ними интереснее)
npm run seed

# 6. Запустить
npm start
```

Сервер поднимется на `http://localhost:3000` — порт берётся из `PORT` в `.env`.

### Проверка, что всё живо

```bash
curl http://localhost:3000/health
curl http://localhost:3000/health/ready
```

Первый отвечает без обращения к базе, второй проверяет соединение с ней. Если `/health` отвечает, а `/health/ready` возвращает 503 — приложение работает, а до базы не достучалось: смотрите параметры `DB_*` в `.env`.

Список всех маршрутов отдаёт корень: `curl http://localhost:3000/`

### Запуск базы в контейнере вместо локальной

Если не хочется ставить PostgreSQL на машину:

```bash
docker compose up -d     # поднимет postgres:16 с параметрами из .env
npm run migrate
npm start
```

Остановить: `docker compose down`.

### Если что-то не поднимается

| Симптом                                       | Причина и что делать                                                                                                          |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `EADDRINUSE: address already in use :::3000`  | порт занят другим приложением. Запустить на другом: `PORT=3001 npm start` — или найти занявшего: `netstat -ano \| grep :3000` |
| `база данных "music_store" не существует`     | пропущен шаг 3 — выполните `createdb -U postgres music_store`                                                                 |
| `password authentication failed`              | неверные `DB_USER` / `DB_PASSWORD` в `.env`                                                                                   |
| `/health/ready` отдаёт 503                    | PostgreSQL не запущен либо `DB_HOST` / `DB_PORT` указывают не туда                                                            |
| `make: command not found`                     | на Windows `make` не установлен. Все цели продублированы в `npm run` — см. таблицу ниже. Поставить: `choco install make`      |
| Проверка качества падает на нетронутых файлах | окончания строк. `.gitattributes` фиксирует LF; после его появления однократно выполните `git add --renormalize .`            |

### Остановить

`Ctrl+C` в терминале с сервером. Если запускали в фоне — найдите процесс по порту:

```bash
netstat -ano | grep :3000
```

## Команды

Единый интерфейс через `make` (методичка §Рекомендуемый командный интерфейс):

| Команда                 | Действие                                             |
| ----------------------- | ---------------------------------------------------- |
| `make setup`            | установка зависимостей, создание `.env`              |
| `make run`              | локальный запуск                                     |
| `make test`             | автоматические тесты                                 |
| `make quality`          | форматирование и статический анализ                  |
| `make migrate`          | применение миграций                                  |
| `make rollback`         | откат последней миграции                             |
| `make seed`             | демонстрационные данные                              |
| `make verify`           | **полный набор локальных проверок** (quality + test) |
| `make up` / `make down` | контейнер с БД                                       |

Без `make` доступны те же шаги через `npm run <script>` — см. `package.json`.

## Конфигурация

Только через переменные окружения (шаблон — `.env.example`):

| Переменная                | Назначение        | По умолчанию            |
| ------------------------- | ----------------- | ----------------------- |
| `NODE_ENV`                | окружение         | `development`           |
| `PORT`                    | порт HTTP-сервера | `3000`                  |
| `DB_HOST` / `DB_PORT`     | адрес PostgreSQL  | `127.0.0.1` / `5432`    |
| `DB_USER` / `DB_PASSWORD` | учётные данные    | `postgres` / `postgres` |
| `DB_NAME`                 | имя базы          | `music_store`           |

Файл `.env` находится в `.gitignore` и **никогда не попадает в репозиторий**.

## Правила внесения изменений

Раздел выполняет пункт 11 ЛР1 и является обязательным для всех участников.

### Порядок работы

1. **Задача.** Любое изменение начинается с задачи (issue) с понятной формулировкой результата.
2. **Ветка.** От `main` создаётся отдельная ветка: `feature/<краткое-имя>`, `fix/<краткое-имя>`, `docs/<краткое-имя>`.
3. **Коммиты.** Несколько осмысленных коммитов в стиле Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`. Сообщение объясняет **зачем**, а не пересказывает диф.
4. **Локальная проверка.** До пуша обязателен зелёный `make verify`.
5. **Запрос на слияние.** Pull Request в `main` с описанием: что меняется, зачем, как проверено. Прямой push в `main` запрещён.
6. **Проверка изменений.** PR читает другой участник команды. Замечания закрываются новыми коммитами в той же ветке.
7. **Слияние.** Только после зелёных проверок и одобрения. После слияния ветка удаляется.

### Обязательные команды проверки

```bash
make verify     # эквивалент: make quality && make test
```

`make verify` обязан быть зелёным **до** создания PR и **перед** слиянием. Он включает:

- `npm run format:check` — соответствие форматированию Prettier;
- `npm run lint` — статический анализ ESLint (0 ошибок);
- `npm test` — весь набор тестов Jest.

### Запрещённые действия

- Удалять или отключать тесты, чтобы проверка прошла.
- Отключать правила анализаторов, снижать пороги качества, ослаблять проверки ради «зелёного» результата.
- Коммитить секреты: `.env`, пароли, ключи, токены, дампы с реальными данными.
- Пушить напрямую в `main` и делать `force-push` в `main`.
- Править применённые миграции — исправление вносится **новой** миграцией.
- Менять критические файлы приёмки (`Makefile`, `migrations/`, `.github/`, `docker-compose.yml`, `TZ.md`) незаметно: такие правки выносятся в описание PR отдельным пунктом и проверяются дополнительно.

### Порядок приёмки

Изменение считается принятым, когда одновременно выполнено:

1. Задача закрыта тем PR, который её реализует.
2. `make verify` зелёный на ветке.
3. PR прочитан и одобрен другим участником; замечания закрыты.
4. Изменения критических файлов приёмки явно перечислены в описании PR.
5. Секреты и локальные файлы в диф не попали.
6. Ветка слита в `main`, релизная точка при необходимости помечена тегом (`v0.1.0`, ...).

## Зоны ответственности

Проект делится на 2–3 зоны (методичка §Список проектов):

- **Каталог** — музыканты, жанры, карточки пластинок, архивация и возврат.
- **Склад и продажи** — поступления, продажи, остатки, ключевое правило «нельзя продать больше остатка».
- **Инфраструктура и качество** — миграции, конфигурация, тесты, `make`, CI.

## Ключевое правило предметной области

Нельзя продать больше, чем есть на остатке. Продажа выполняется в транзакции: проверка остатка → фиксация снимка цены в `sales.unit_price` → уменьшение `records.stock`. Нарушение отдаёт **HTTP 409** с кодом `INSUFFICIENT_STOCK`.

Музыканты и пластинки **не удаляются физически** — они уходят в архив (`archived_at`) и могут быть возвращены. Благодаря этому история продаж неуничтожима.
