# Конфликт слияния: разбор

Документ выполняет пункт 9 ЛР1 — смоделировать и разрешить конфликт слияния.

## Как конфликт был получен

Задача «корневой индекс API» (`GET /`) была независимо взята двумя участниками команды. Обе ветки выросли из одного коммита `f4020d8`, то есть ни одна не видела работу другой:

```
                      ┌── feature/api-index          (плоский список маршрутов)
f4020d8 ──────────────┤
                      └── feature/api-index-grouped  (группировка по ресурсам)
```

Первым был слит `feature/api-index-grouped` (PR #4). После этого `feature/api-index` (PR #3) перестал сливаться автоматически: GitHub сообщил, что ветку нельзя объединить без ручного вмешательства.

## Почему конфликт возник именно здесь

Обе ветки **создали один и тот же новый файл** `src/routes/root.js` с разным содержимым — git классифицирует это как конфликт типа `add/add`. У файла нет общей базовой версии, поэтому автоматически выбрать «правильную» сторону невозможно.

Два других изменённых файла слились без конфликта:

| Файл                 | Результат              | Почему                                                                              |
| -------------------- | ---------------------- | ----------------------------------------------------------------------------------- |
| `src/routes/root.js` | **конфликт `add/add`** | обе ветки создали файл с разным содержимым                                          |
| `src/app.js`         | слился чисто           | обе ветки внесли **дословно одинаковые** строки: подключение и монтирование роутера |
| `tests/root.test.js` | слился чисто           | тест написан одинаково, проверки не зависят от формы ответа                         |

Это важный вывод: конфликт возникает не от того, что «двое трогали один файл», а от того, что они изменили **одни и те же строки по-разному**. Одинаковые правки git сводит молча.

## Что показал git

```
$ git merge main
Auto-merging src/routes/root.js
CONFLICT (add/add): Merge conflict in src/routes/root.js
Automatic merge failed; fix conflicts and then commit the result.
```

Содержимое файла с маркерами (фрагмент):

```js
const express = require('express');
<<<<<<< HEAD
const { version } = require('../../package.json');
=======
const { version, description } = require('../../package.json');
>>>>>>> main
```

- `<<<<<<< HEAD` — версия текущей ветки (`feature/api-index`, плоский список);
- `=======` — граница;
- `>>>>>>> main` — версия вливаемой ветки (группировка, уже в `main`).

Всего конфликтующих участков было два: импорт из `package.json` и тело ответа.

## Как разрешён

Решение принято по существу, а не «оставить свою версию»:

| Что              | Решение                           | Обоснование                                                                           |
| ---------------- | --------------------------------- | ------------------------------------------------------------------------------------- |
| Структура ответа | взята **группировка по ресурсам** | из неё видно структуру предметной области и все методы, а не только адреса для чтения |
| Поле `docs`      | **сохранено** из плоской версии   | ссылка на `docs/API.md` — полезная точка входа для того, кто открыл сервис впервые    |
| Поле `service`   | **отброшено**                     | дублировало `name` + `description`, которые и так берутся из `package.json`           |
| Импорт           | `{ version, description }`        | нужен для варианта с группировкой                                                     |

Итоговый ответ `GET /`:

```json
{
  "name": "music-store",
  "description": "Складской учёт магазина виниловых пластинок",
  "version": "0.1.0",
  "docs": "docs/API.md",
  "resources": {
    "health": ["GET /health", "GET /health/ready"],
    "genres": ["GET /genres", "POST /genres", "PATCH /genres/:id", "DELETE /genres/:id"],
    "sales": ["GET /sales", "POST /sales"],
    "reports": ["GET /reports/top-sellers"]
  }
}
```

## Порядок команд

```bash
git checkout feature/api-index
git merge main                  # -> CONFLICT (add/add) в src/routes/root.js
# правим файл: убираем маркеры, сводим обе версии в одну
git add src/routes/root.js
git commit                      # фиксируем разрешённое слияние
npm test && npx eslint .        # проверяем, что результат жив
git push
```

Ключевое: `git add` конфликтного файла — это и есть заявление «конфликт разрешён». Пока файл не добавлен в индекс, git не даст завершить слияние.

## Проверка после разрешения

- `GET /` отвечает 200 и содержит все разделы API;
- 36 тестов зелёные, ESLint 0 ошибок, Prettier чисто;
- маркеры `<<<<<<<`, `=======`, `>>>>>>>` в коде отсутствуют.

Последнее стоит проверять отдельно: незамеченные маркеры — самая частая ошибка при разрешении конфликта, и код с ними обычно даже не парсится.
